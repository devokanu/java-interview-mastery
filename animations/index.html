AccountTransferService.java

public TransferResult transfer(TransferCommand command) {
    validate(command); // hesaplar, tutar ve idempotency key
    return transactionalTransfer(command);
}

@Transactional
TransferResult transactionalTransfer(TransferCommand command) {
    Account source = accountRepository.lockById(command.fromAccountId());
    Account target = accountRepository.lockById(command.toAccountId());
    source.debit(command.amount());
    target.credit(command.amount());
    transferRepository.save(new Transfer(source, target, command.amount()));
    auditRepository.save(Audit.transferRequested(command));
    outboxRepository.save(TransferCompletedEvent.from(command));
    return TransferResult.accepted(); // method bitince commit denenir
}

// Ayri worker: DB commit olduktan sonra calisir
void publishOutboxEvent(OutboxEvent event) {
    notificationClient.sendTransferSms(event); // basarisizsa retry
}

Kavram: Transaction Boundary

Transaction boundary, "bu DB islemleri ya birlikte basarili olsun ya da birlikte geri alinsin" dedigimiz sinirdir. Transferde para dusme, para ekleme ve transfer kaydi bu sinirda olmalidir.

Kavram: Rollback

Rollback, commit edilmemis DB degisikliklerinin geri alinmasidir. Ama rollback sadece transaction'a dahil kaynagi etkiler; dis HTTP cagrisini geri alamaz.

Banking Riski

SMS transaction icinde gonderilir ve sonra DB rollback olursa musteri "transfer tamamlandi" mesaji alir ama sistemde transfer yoktur. Bu audit ve operasyon riski dogurur.

Senior Yaklasim

  • Para hareketi DB transaction icinde tutulur.
  • Dis bildirim transaction icine alinmaz.
  • Outbox kaydi ayni transaction icinde yazilir.
  • Commit sonrasi worker bildirimi retry edebilir.

Mulakat Sorusu ve Senior Cevap

TR Soru

Bir banka transferinde `@Transactional` boundary nereye konur? SMS/HTTP bildirimi transaction icinde yapilmali mi?

TR Senior Cevap

Boundary para hareketinin atomik olmasi gereken servis use-case'ine konur: debit, credit, transfer kaydi ve audit/outbox kaydi ayni transaction icinde olmalidir. SMS/HTTP gibi dis etkiler transaction icinde yapilmaz; outbox ile commit sonrasinda retry edilebilir sekilde yonetilir.

EN Question

Where would you place the `@Transactional` boundary in a banking transfer? Should SMS/HTTP notification happen inside the transaction?

EN Senior Answer

I would place the boundary around the atomic money-movement use case: debit, credit, transfer record, and audit/outbox insert. I would not call SMS/HTTP inside the DB transaction; I would publish it after commit through an outbox with retry and monitoring.

02 - @Transactional Rollback Rules: Checked vs Unchecked Exception

Bu bolum, Spring'in varsayilan rollback davranisini gosterir: RuntimeException ve Error rollback yapar; checked exception ise `rollbackFor` yazilmadikca varsayilan olarak rollback yapmaz.

1. Baslangic Transaction acilir. Debit ve credit henuz commit edilmedi.
2. Business validation Yetersiz bakiye gibi beklenen durumlar tercihen state degismeden yakalanir.
3. RuntimeException Beklenmeyen teknik hata. Spring default rollback yapar.
4. Checked exception Spring default rollback yapmaz. Bu kural banking icin riskli olabilir.
5. rollbackFor Checked exception da finansal butunlugu bozuyorsa acik rollback kuralidir.
RollbackRulesExample.java

void validateBeforeTx(TransferCommand command) {
    if (!accountService.hasEnoughBalance(command)) {
        throw new InsufficientBalanceException();
    }
}

@Transactional
void transferDefaultRules(TransferCommand command)
        throws TransferFileException {
    accountService.debit(command);
    accountService.credit(command);
    fraudClient.check(command); // RuntimeException olursa rollback
    fileGateway.writeTransferFile(command); // checked exception default rollback yapmaz
}

@Transactional(rollbackFor = TransferFileException.class)
void transferSafeForBanking(TransferCommand command)
        throws TransferFileException {
    accountService.debit(command);
    accountService.credit(command);
    fileGateway.writeTransferFile(command);
}

Checked Exception

Compiler'in yakalamaya veya `throws` ile bildirmeye zorladigi exception turudur. Ornek: IOException.

Unchecked Exception

RuntimeException ve alt siniflaridir. Spring varsayilan olarak rollback yapar.

Banking Riski

Checked exception para hareketini yarim birakabilecekse rollback kuralini varsayima birakma; `rollbackFor` ile acik yaz.

Mulakat Sorusu ve Senior Cevap

TR Soru

Spring `@Transactional` varsayilan olarak hangi exception turlerinde rollback yapar?

TR Senior Cevap

Varsayilan olarak RuntimeException ve Error icin rollback yapar, checked exception icin rollback yapmaz. Banking gibi para butunlugunun kritik oldugu sistemlerde checked exception da transaction'i bozuyorsa `rollbackFor` ile acik rollback tanimlarim.

EN Question

By default, for which exception types does Spring `@Transactional` roll back?

EN Senior Answer

By default, Spring rolls back on RuntimeException and Error, but not on checked exceptions. In banking systems, if a checked exception can break money-movement consistency, I explicitly configure `rollbackFor`.
